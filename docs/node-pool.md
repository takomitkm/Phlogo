# 节点池

本文档介绍 Phlogo Gnosis的节点池：节点如何入库、如何去重、如何与来源关联，以及存活状态如何判定。

## 工作流程

worker 的 Fetch 闭环每轮处理启用的来源，逐个：

1. 依据节点属性计算稳定指纹（fingerprint v1：协议 + 地址 + 端口 + 认证 + 传输 + TLS 的 SHA-256），找出已存在的节点。
2. 更新已有节点的内容，或创建新节点。
3. 维护节点与来源的对应关系（原子替换/累积，失败保留旧关联）。
4. 清理该来源中已经消失的节点关联；不再被任何来源引用的节点进入 `Orphaned`，保留窗口（`orphan_retention_days`，默认 14 天）过后 Retired 并物理删除。

测活由 worker 的 CheckJob 经 **MiaoSpeed WebSocket** 执行（初筛 + 复筛）。结果写入历史和评分，不直接修改节点与来源的对应关系。

## 节点去重

节点池中的每个节点代表一个去重后的代理实体，以 **fingerprint v1**（canonical 字符串的 SHA-256 前 16 字节 hex）去重：同一节点即使出现在多个来源中，也只会保存一份。

新抓取到的节点初始 `membership='Linked'`、无测活数据、评分为 0，需经过初筛后才会参与分发。已有节点在更新内容时会保留其测活历史，因此延迟等历史数据不会因为来源重新抓取而丢失。

## 节点与来源的关联

节点与来源是多对多关系：

- 一个节点可以来自多个来源。
- 一个来源可以提供多个节点。

当某个来源的抓取结果显示某节点已消失时，Phlogo Gnosis只删除该来源与该节点的关联。若该节点仍被其他来源引用，则继续保留；若不再被任何来源引用，则连同其测活历史和评分一起删除。

对于抓取失败的来源，Phlogo Gnosis会保留其原有节点，直到该来源被判定为失效后才清理关联。这样可避免一次临时抓取失败就丢失整个来源的节点。

## 节点字段

| 字段 | 说明 |
| --- | --- |
| `identity_hash` | 用于去重的稳定指纹（fingerprint v1）。 |
| `protocol` / `server` / `port` | 节点协议与地址。 |
| `membership` | 生命周期状态：`Linked` / `Orphaned` / `Retired`。 |
| `region` | 出口地区，由最近一次测活结果的复筛给出（存于结果 metrics）。 |
| `health` | 按测活视角（tag）的存活状态：`alive` / `degraded` / `dead`。 |
| `score` | 节点综合评分（EWMA，按 tag 记录于 `node_scores`）。 |
| `source_ids` | 与该节点关联的来源列表。 |

> 本实现的 API 面**不返回**节点密码/原始配置（凭据安全边界）；原始配置进入订阅载荷需经加密层（规划中）。

## 存活判定

存活状态由初筛结果决定，与评分相互独立。

本实现在 `node_alive_check_window_minutes`（默认 240）窗口内，查询每个「节点 + 测活视角 tag」的最新状态（`node_status`）：

- 只要有一个 tag 的最新状态为 `alive`/`degraded`，节点即参与分发（跨 tag OR 合并）。
- 窗口外无任何成功记录的节点视为未存活。

由于不同测活视角可以位于不同网络环境，同一节点在不同 tag 下的可用性可能不同。

## 管理界面操作

管理界面的「节点管理」页面提供以下操作：

- 按存活状态、地区、协议、地址、来源、评分区间和测活视角 tag 筛选节点。
- 高级搜索：`POST /api/v1/nodes/search`（Filter-AST JSON，见 [配置与 API](configuration-and-api.md) 的筛选引擎节）。
- 查看节点详情、关联来源，以及按 tag 的初筛与复筛历史时间线。
- 删除节点。
